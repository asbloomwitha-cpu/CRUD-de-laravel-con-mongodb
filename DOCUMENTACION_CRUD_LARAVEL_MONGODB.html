1 Introducción y Objetivos

El objetivo central de este proyecto es la construcción de una aplicación web empresarial bajo la arquitectura MVC de Laravel 13, sustituyendo el tradicional motor relacional SQL por MongoDB, el motor de base de datos NoSQL líder a nivel mundial.

A través de esta implementación, se logra un sistema para la gestión de productos tecnológicos (creación, lectura, actualización y eliminación) con soporte para atributos dinámicos y documentos BSON embebidos, demostrando las ventajas de los esquemas flexibles NoSQL.

2 Requisitos Previos e Instalación del Driver

Para que PHP se comunique de forma nativa con MongoDB sobre Linux (Ubuntu/Debian), es indispensable compilar e instalar la extensión PECL mongodb.so: 

# 1. Instalar dependencias de compilación
sudo apt update && sudo apt install -y php8.3-dev php-pear build-essential libssl-dev

# 2. Compilar la extensión oficial de MongoDB
sudo pecl install mongodb

# 3. Habilitar la extensión para PHP 8.3
echo "extension=mongodb.so" | sudo tee /etc/php/8.3/mods-available/mongodb.ini
sudo phpenmod -v 8.3 mongodb

# 4. Verificar presencia del módulo
php -m | grep mongodb

3 Integración con Laravel: `mongodb/laravel-mongodb`

Se incorporó la librería oficial de MongoDB para Eloquent en el archivo composer.json: 

composer require mongodb/laravel-mongodb
Configuración en .env:
DB_CONNECTION=mongodb
MONGODB_URI=mongodb://127.0.0.1:27017
MONGODB_DATABASE=mi_base_de_datos
SESSION_DRIVER=file (garantiza sesiones estables e independientes de SQL)

4 Migración NoSQL y Definición de Índices

Aunque MongoDB no requiere tablas rígidas, se utilizó el sistema de migraciones de Laravel para crear la colección productos y generar índices optimizados sobre los campos más consultados: 

// database/migrations/2026_09_23_143057_create_productos_table.php
Schema::connection('mongodb')->create('productos', function (Blueprint $collection) {
    $collection->index('nombre');
    $collection->index('categoria');
});

5 Modelo Eloquent NoSQL (`Producto`)

El modelo hereda de MongoDB\Laravel\Eloquent\Model, lo que le confiere compatibilidad directa con las consultas de Eloquent manteniendo la identidad NoSQL: 

namespace App\Models;

use MongoDB\Laravel\Eloquent\Model;
use Illuminate\Database\Eloquent\Factories\HasFactory;

class Producto extends Model
{
    use HasFactory;

    protected $connection = 'mongodb';
    protected $collection = 'productos';

    protected $fillable = [
        'nombre', 'descripcion', 'precio', 'stock', 'categoria', 'atributos', 'estado'
    ];

    protected $casts = [
        'precio' => 'float',
        'stock' => 'integer',
        'atributos' => 'array',
        'estado' => 'boolean',
    ];
}

6 Controlador RESTful (`ProductoController`)

Se implementaron las 7 acciones CRUD fundamentales en app/Http/Controllers/ProductoController.php:

Método Ruta Acción Descripción
GET /productos index() Listado paginado, métricas de inventario y filtros combinados.
GET /productos/create create() Formulario para ingresar nuevo producto y atributos dinámicos.
POST /productos store() Validación y almacenamiento de documento BSON en MongoDB.
GET /productos/{id} show() Visualización de ficha técnica e inspector JSON/BSON crudo.
GET /productos/{id}/edit edit() Formulario con datos precargados para modificación.
PUT /productos/{id} update() Actualización atómica en la base de datos NoSQL.
DELETE /productos/{id} destroy() Eliminación segura con modal de confirmación.

7 Interfaz de Usuario de Alto Nivel (Blade + Tailwind)

La interfaz de usuario fue diseñada con un enfoque Dark Glassmorphism, brindando una experiencia moderna:

  • Indicador en vivo de estado NoSQL: Monitor de conexión en la barra de navegación que muestra la dirección del motor (127.0.0.1:27017) y base de datos activa.
  • Métricas Clave (KPIs): Tarjetas con cálculo en tiempo real del Total de Productos, Valor Financiero del Inventario, Alertas de Stock Bajo y Categorías.
  • Constructor Dinámico de Atributos: Interfaz en JavaScript para añadir propiedades clave-valor personalizadas en tiempo de ejecución.
  • Inspector BSON: Visor en formato JSON para que el evaluador verifique los datos directos del documento.
